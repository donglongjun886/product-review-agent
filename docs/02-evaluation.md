# 评测

一套商品内容治理系统，判一个商品该放行（PASS）、该下架（REJECT），还是拿不准交给人（HUMAN_REVIEW）。
评测要回答的是同一个问题：**同一批案子，三条做法各自解决了什么**。正式评测只跑**真实数据 × 真实模型**：
事实来自生产装配（真 MySQL + 真 RAG），结果是单次抽样、不确定、不可重放，不进 CI。这份文档写的是评测
口径 —— 三条臂各能看到什么材料、事实从哪来、真值从哪来、指标怎么读、哪些结论不能下。

## 三条臂

三条臂跑同一份案源、进同一套指标计算；差异只归因于**谁允许用基础输入之外的材料**，所以材料边界钉死：

| 臂 | 材料边界 | 模型 | 工具 |
|---|---|---|---|
| `rule` | 只对案件快照跑确定性初筛 | 不用 | 不用 |
| `single` | 只喂案件快照，一次直判 | 一次调用 | 不用 |
| `agent` | 案件快照 + 按证据缺口动态调查 | 多步 | 生产工具集 |

- `rule` 直接复用线上三分流：判放行记 PASS、判拒绝记 REJECT、判"复杂，需要进一步查"记 **HUMAN_REVIEW**。
  口径差异要写明：**线上复杂案交给 Agent 终裁，评测里记 HUMAN_REVIEW** —— 评测语义是"没有 Agent 时，
  复杂案只能人工"，两者不是一回事。
- `single` 不调工具、不过 Gate：它代表"没有调查能力时，模型靠案件快照能走多远"。
- `agent` 是完整调查：提假设 → 定计划 → 动态挑工具 → 多源取证（含检索）→ 复核 → 三分类决策，
  终裁必须过事实证据与 Gate 校验，不采信模型自报的假设与置信度。

三条臂都跑**生产默认预算档**，评测不覆盖档位：预算够不够用本身是被测行为，超限按生产语义转人工。
`rule` 零模型成本、确定性；`single` 与 `agent` 需要真实模型配置、有费用、非确定性。

## 事实来源

评测的事实来源是**生产装配**，不另造一套评测世界：

- 商品与商家读**真 MySQL**；案例与政策走**真 RAG**（混合召回）。
- `rule` 与 `single` 只吃案件快照，不使用工具；`agent` 用生产工具集，材料可以超出案件快照。
- 三条臂共享同一份案件快照；可比性由**材料边界**保证，而不是靠复制一份数据世界。
- 依赖或检索不可用时显式失败、记为失败，不得返回空结果冒充正常。

## 评测集

案源是随代码入版本库的数据集 v2，按场景分层（明确正常 / 明确违规 / 边界 / 多信号组合 / 对抗规避）。
每条案子的真值不只有 PASS/REJECT，还包括风险类型、风险等级、期望证据类型、期望调用的工具与应引用的
政策 —— 只有这样才能区分"结论蒙对了但理由错了"。两条取数口径：

- 进评测集的种子案不得再进 RAG 语料，否则检索会命中被考的那条；这条由测试守住。
- 期望工具为空 = 没标注，不是"应该调用 0 个工具"，这类案不计入工具选择指标的分母。

**数据集 v2 的真值是旧世界标的，待按规则书重标**：判定口径、阈值与材料边界都变了，旧真值不能直接当
当前口径的答案。重标路线按三步走：

1. **规则书**先定死每条案子的判定口径与期望证据；
2. **独立模型预标注**：由一个不参与生产判定的模型按规则书给初标；
3. **人工抽检**：对预标注抽样复核，覆盖各场景分层与边界案。

重标完成后真值随规则书冻结；规则不变时，真值不因评测跑分回改。

## 指标怎么算

### 三个分母不能混读

指标按分母分成三组，引用任何一个都要说清它属于哪一组：

| 分母 | 案集 | 指标 |
|---|---|---|
| 全量 | 全部案（含真值为 HUMAN_REVIEW 的案） | `automation_coverage`、`human_review_rate` |
| AUTO_DECIDABLE | 真值是 PASS / REJECT 的案 | `accuracy`、`precision`、`wrong_auto_decision_rate` |
| 真值 REJECT | 真值是 REJECT 的案 | `recall`、`reject_unhandled` |

拿不准就交给人（abstention）：系统不硬判，输出 HUMAN_REVIEW；这是克制不是错误，也不能当普通第三分类
混进准确率。

### 主指标表

| 指标 | 它回答什么问题 | 分母 | 数据从哪来 |
|---|---|---|---|
| Accuracy 准确率 | 判对了多少 | AUTO_DECIDABLE 案；**输出转人工也算错** | 预测决策 × 期望决策 |
| Precision 精确率 | 判 REJECT 的有多少是真违规（判错会误伤商家） | 被自动判 REJECT 的案 | 同上 |
| Recall 召回率 | 真违规被自动拦下多少（漏放会损害平台） | 真值是 REJECT 的案；**转人工算未拦下**（入分母不入分子） | 同上 |
| wrong_auto_decision_rate 自动判错率 | 自动定下来的案里错的比例 | AUTO_DECIDABLE 里被自动裁决的案 | 预测决策 |
| reject_unhandled 该拒却转人工率 | 真违规有多少没被自动拒、而是安全地转给了人工 | 真值 REJECT 的案 | 预测决策 |
| human_review_rate 转人工率 / automation_coverage 自动化率 | 人工要接多少活、多少案是自动定的 | 全部案 | 预测决策 |

几条容易踩的坑：准确率的分母是 AUTO_DECIDABLE，输出转人工按错算，这比"只算自动判决的案子"更严，
是为了逼着自动化率与安全一起看；精确率与自动判错率只在自动裁决的案子里算，转人工不进它们的分母。
`recall` 与 `reject_unhandled` 的分母都是**全部真值 REJECT 案**，转人工在两者里都算"没被自动拦下"；
真值 REJECT 案被"自动拒绝 / 转人工 / 自动放行"三个互斥桶完全划分，故恒有
**`recall` + `reject_unhandled` + 漏放率 = 1** —— 看 `recall` 的缺口时必须再用 `reject_unhandled`
区分它是**安全的转人工**还是**危险的漏放**。**自动化必须和安全一起读** —— 只有方案能把复杂案里的
一部分安全地自动化（自动化率上升，同时自动判错率与 `reject_unhandled` 不恶化）时，才谈得上是价值。

### Agent 专用指标

| 指标 | 它回答什么问题 | 分母 | 数据从哪来 |
|---|---|---|---|
| Tool Selection Accuracy 工具选择准确率 | 该调的工具调了没有 | 标注了期望工具的案 | 期望工具集合 × 实际调用集合 |
| redundant_tool_rate 多余调用率 | 调了多少没必要的工具 | 标注了期望工具的案 | 实际调用集合 |
| risk_type_coverage 风险类型命中率 | 风险类型说对了多少 | 标注了期望风险类型的案 | 期望值 × 输出值 |
| risk_level_agreement 风险等级一致率 | 风险档位说对了多少 | 标注了期望风险等级的案 | 期望值 × 输出值 |
| evidence_gain_rate 有效取证率 | 工具调用里多少带来新证据 | 成功的工具调用 | 调查轨迹 |
| decision_changed_rate 结论翻转率 | 多少工具调用改变了结论 | 成功的工具调用 | 调查轨迹 |

这些指标只在 `agent` 臂上有意义（`rule` 与 `single` 不调工具）。取数规则：期望工具、期望风险类型、
期望风险等级为空的案不进分母；"结论对但理由错"的语义判定无法自动化，上述两项是**自动代理**。
**预算占用率不出数** —— 记录里没有随案冻结的预算上限，硬算只能拿当前配置去套历史运行，那是**伪造观测**。

### 成本怎么记

每次运行报模型调用次数、工具调用次数、token 数的均值、P50、P95，以及整次运行的墙钟时间。
token 是硬数，真实调用的费用按官方价估算；延迟是进程内墙钟量，只在真实模型运行时才有。

### 阈值不随数据集调

预算上限是**工程初始值**，写在生产真正读它的那处常量里，**没有在评测数据集上拟合过，也不会因为评测
结果回改**；具体取值以代码为准。评测也不为"方便观察"放宽生产预算档位。

## 口径边界

- **单次抽样只代表那一次运行**：真实模型非确定性、不可重放，同案重跑输出可能不同；不做重复采样，
  也不为改分调提示词。
- **真值重标完成前，跑分只说明链路能跑通**，不能外推成调查能力或模型水平。
- **三条臂的差异是"允许用多少基础输入之外的材料"的整体差异**，不可分解归因于"主动调查"这一项；
  工具的必要性改用期望工具覆盖如实标注，期望为空的工具不做"不必要"的判定。
- **不同世界的数字不得混算或互相暗示**：数据集重标前后的结果、真实模型与桩路径的结果，都不构成同一次
  评测的对照。
